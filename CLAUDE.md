# Free Fire Zone — BACKEND (game server)

Frontend (3D client) lives at `../Free-fire-zone`. Colyseus 0.18 + MongoDB. The game is online with real players only (no bots).

Detailed documentation: `docs/server.md` (room lifecycle, round machine, hit checks, shop, persistence, reporters, deploy, recipes) and `docs/protocol.md` (every client/server message, synced state, the constants mirrored in the client). The client's docs are in `../Free-fire-zone/docs/` (start at its `README.md`). Read the relevant page before a change and update it when the change makes it wrong.

- `npm start` (tsx watch, port 2567), `npm run build` (tsc -> `build/`), `npm test` (mocha + `@colyseus/testing`; Mongo faked via `__setPlayersForTest`, the Bloxity token check via `__setVerifierForTest`; tests share one booted server, `test/server.ts`, and shorten `PHASES` / `TIMING`). Node >= 22. Local testing: `ROUND_SECONDS=30 npm start` shortens rounds (ignored in production).
- One room type, `match` (`src/rooms/MatchRoom.ts`, state `src/rooms/schema/MatchState.ts`). Up to `ROOM_MAX_CLIENTS` (6) connections per room (the lobby) = a round's seats, two teams of `TEAM_MAX` (3), so the matchmaker opens another room instead of queueing; a player who pressed Play without a seat (e.g. an odd squad split) still queues (`inMatch`, no team) and is seated first next round. Everyone in the room starts in the menus; `play` puts them in the round. A round needs `MIN_PLAYERS` (2) who pressed Play, then runs `vote` (15 s; the winning map's `MAPS[i]` in `rules.ts` (`world` + `focus`) picks the zone plan (`WORLDS`) and steers the zone planner in `zone.ts`, mirrored by the client's `MAPS` / `WORLDS`; maps 0-2 are on Coral Key, map 3 is Dustline Ridge, a larger island) -> `intro` -> `countdown` -> `playing` -> `ending` -> `results` and the next round starts in the SAME room (CrazyGames rule). Players who press Play mid-round join at once if a seat is free (team balanced; party members share a team).
- Squad (lobby team, `src/rooms/MatchRoom.ts`, state `squad` / `squadLead`): players invite each other from the lobby (`invite` -> `inviteReply`, 20 s expiry, `squadNote` / `invite` / `inviteEnd` messages), up to `SQUAD_MAX` (3); only the leader presses `play` and the whole squad is queued; squads are seated on one side (`pickTeam`, `startRound`). Docs: `docs/server.md` 5.4, `docs/protocol.md`; tests `test/Squad.test.ts`.
- Authority: the client moves itself (`pose`, bounded: `WORLD_BOUND`, `MAX_SPEED` + `MOVE_SLACK`, teleports only in the grace after a spawn). The shooter's client reports hits (`hit` { t, w, s shot number, n pellets, h head, d }); the server checks fire rate (per shot number, `FIRE_RATE_SLACK`), the weapon is in the loadout, teams, alive, spawn protection and range (server positions + `RANGE_SLACK`), then applies damage with armour (`rules.ts`, a copy of the client's config.js values) and decides knocks (a teammate standing), eliminations, assists, streaks, score and the round end. Frags: `throw` then `boom` { x, y, z, t: targets }; revives: `reviving` then `revive` after `HEALTH.reviveTime`; `heal`, `ult` (rook damage cut, jin heals), `fell`, `respawn` (>= `RESPAWN_MIN_S` after death), `open` crates/airdrops (armour is rolled here; crates refill on the round clock), zone damage / regen / bleed-out on the server tick. Relays for the others' eyes (never back to the sender): `shot`, `throw`, `boom`, `wall`, `ult`, `emote`. Spectating (eliminated players): `spectate` { t } sets state `watch`; `heart` / `react` (rate-limited, only for the player watched) -> state `hearts` + broadcasts `heart` / `react`; `profileOf` -> `playerProfile` (level, rank points, career and round stats). State `level` (`levelOf` career stats) and `rp` feed the spectate card. Events sent: `dmg`, `knock`, `elim`, `revive`, `spawn`, `opened`, `matchEnd`, `round`, `rewards`, `reward` (to the shooter: what a knock / elimination granted), `healed` (a medic weapon healed a teammate). Weapon rules may carry `melee`, `pierce` (armour-piercing), `heal` (the Mender: hits on teammates heal), `burst` / `burstGap` (burst fire-rate check), `blast` (launchers: the shooter reports `blast` { w, s, x, y, z, t }, relayed, falloff damage) and `block` (the frying pan in the melee slot cuts body shots from behind; `dmg.b`); the loadout has a melee slot (`melee`, state `melee`, `carries`); `throw` uses the loadout's grenade (`GRENADES`, `effect`: sticky, fire (server-ticked burning patches, `fires` / `burnFires`), smoke, flash; `boom` relays carry the kind `k`). Tests: `test/Arsenal.test.ts`.
- The zone is planned from the round's `zoneSeed` with `mulberry32` (`src/zone.ts`); the client's `src/game/zone.js` runs the same planner with the same call order, so both agree without streaming circles. Each world has its own plan and land radius (`WORLDS`: Coral Key `ZONE` + `ISLAND_RADIUS` 125, Dustline Ridge 330 m start, radius 250); `test/Zone.test.ts`.
- Vehicles (`src/vehicles.ts`, `docs/server.md` 5.9b): Dustline Ridge rounds park a Jeep and a Dune Buggy in each camp (`VEHICLE_SPAWNS`, state `vehicles`). The server owns the seats (`enter { v, s }` in range and free, `exit`; knocks, eliminations, respawns eject; leaving releases) and players' `veh` / `seat`; the vehicle's pose comes from its `owner` (the driver, or the last driver until it reports `r: 1` at rest) via `vpose`, bounded by `VEHICLE_MAX_SPEED` (45) + `VEHICLE_SLACK`, which also applies to seated players' own poses. Combat (`VEHICLE_TYPES` hp, `MOUNTS`, `VEHICLE_DAMAGE` in `rules.ts`, mirrored by the client's config.js): `vhit` (bullets on a hull), `vt` in `boom` / `blast`, a sticky charge on it hurts most, no friendly fire; burns down below 20 %; at 0 a wreck: everyone seated ejected and hurt through armour, a blast around it, `vboom` to all, a new one parked after 30 s (`life` bumped); `ram { v, t, sp }` from the driver (checked: driver, enemy on foot, speed, reach, 0.9 s per target); the Jeep's gunner seat fires `mg` (`mountOf`). Tests: `test/Vehicles.test.ts`.
- Identity (`src/auth.ts`): `onAuth` verifies `options.token` (Legion.SDK.auth.getToken()) with `POST {BLOXITY_API_URL}/v1/auth/game-token/verify` and uses ONLY the returned `user._id`; no/refused token = `guest_<sessionId>` (never saved or reported). `options.devUser` (`dev-...`) is accepted only when `NODE_ENV !== "production"` (local dev saves). `auth` message re-verifies after a mid-session sign-in. One live session per account: a newer one closes the older with `REPLACED_CODE` (4100; the client does not rejoin after it).
- Looks: roster `avatar` (the client's Bloxity look JSON of ids, incl. `characterId`, max `AVATAR_MAX_LEN`) and `outfitKey` (from the verify response's `user.outfitKey` at join, then the player's own `avatar` { avatar, outfitKey } updates; `OUTFIT_KEY` pattern). Cosmetic only, relayed for the others' clients to dress the player.
- Progress (`src/db.ts`, `src/catalog.ts`): the player's profile (coins, gems, rp, owned, loadout, upgrades, stats, mode) lives in Mongo under the verified id; `carriedFrom` guest saves seed a new account once (`carried`). The shop is server-side: `buy` / `equip` (skins / operatives / Store in coins; weapons, grenades and passes in the game's own Gems: `WEAPON_PRICES`, `GRENADE_PRICES`, `PASSES`; prices copied from the client's config.js; nothing is sold for premium currency / Bloxity Gems), answers `shop` and `profile`; `getProfile` re-sends it. Gems (`GEMS` in `rules.ts`, the game's own currency, NOT Bloxity Gems) are granted at each knock / elimination (`reward`) and at the results (`gemsRound`), and must never become purchasable (no real money, Bloxity Gems or ads). Local testing: `DEV_GEMS=5000 npm start` gives brand-new `dev-` accounts Gems (ignored in production). Round rewards (`REWARDS`) are granted at the results; leaving a running round pays half the fighting coins (no participation bonus) and costs rank.
- Missions, rank rewards, first-round tips (`src/progress.ts`, `docs/server.md` 5.13): profile `missions` (3 daily per UTC day + 3 weekly per Monday UTC, rolled in `sendProfile` / `grant` / `claim` by `refreshMissions`), counted from each round in `grant` (`countRound`; `play` / `win` only for rounds played to the end), claimed with `claim { m, i }` -> `claimed` (coins + the game's own Gems); `rankReward` = highest `RANKS` index paid (`payRankUps` in `grant`, once per rank, no back pay for old saves); `tutorial` set by `tutorialDone`; `newsSeen` (the newest lobby announcement closed, client `config.js NEWS.id`) set by `newsSeen { id }`, forward only. `rewards` carries `missions` (ids finished) and `rankUp`. Mirrored by the client's `config.js MISSIONS` / `RANKS`. Tests: `test/Progress.test.ts`.
- Bloxity reporting (`src/reporters.ts`, started in `index.ts`): `installRoomReporter` (Open Rooms directory via `MATCHMAKER_REPORT_URL`), leaderboard scores (`BOARDS` = the client's `LEADERBOARDS`) and player stats (`STAT_DEFINITIONS`) for verified `legion_` ids, batched every `REPORT_EVERY_MS` and at round end. All no-ops without `BLOXITY_REPORT_TOKEN` / `BLOXITY_GAME_ID`.
- Room options: `{ private: true }` = a private room (`?instantMultiplayer=true`, Play with friends). Metadata `{ mode: 1, modeName }` (never a `started` flag: Open Rooms shows started rooms as "Locked").
- CI/CD: `.github/workflows/deploy.yml` tests on PRs and pushes to `main`/`dev`; pushes also build+push a GHCR image and deploy to Bloxity Legion (`main` = prod, `dev` = dev), sending `roomSize` = `ROOM_MAX_CLIENTS` (6) read from `src/constants.ts` (keep it 2-100; never send `seatCap`, per docs.bloxity.io). Needs repo var/secret `LEGION_GAME_ID` (= `free-fire-zone`) and secret `LEGION_DEPLOY_TOKEN`.
- A rule or price change goes in both projects (client `src/config.js` + server `rules.ts` / `catalog.ts`).
