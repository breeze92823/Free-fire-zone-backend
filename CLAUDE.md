# Free Fire Zone — BACKEND (game server)

Frontend (3D client) lives at `../Free-fire-zone`. Colyseus 0.18 + MongoDB. The game is online with real players only (no bots).

- `npm start` (tsx watch, port 2567), `npm run build` (tsc -> `build/`), `npm test` (mocha + `@colyseus/testing`; Mongo faked via `__setPlayersForTest`, the Bloxity token check via `__setVerifierForTest`; tests share one booted server, `test/server.ts`, and shorten `PHASES` / `TIMING`). Node >= 22. Local testing: `ROUND_SECONDS=30 npm start` shortens rounds (ignored in production).
- One room type, `match` (`src/rooms/MatchRoom.ts`, state `src/rooms/schema/MatchState.ts`). Up to `ROOM_MAX_CLIENTS` (18) per room = two teams of `TEAM_MAX` (9). Everyone in the room starts in the menus; `play` puts them in the round. A round needs `MIN_PLAYERS` (2) who pressed Play, then runs `vote` (15 s; the winning map's `MAP_FOCUS` in `rules.ts` steers the zone planner in `zone.ts`, mirrored by the client's `MAPS[i].focus`) -> `intro` -> `countdown` -> `playing` -> `ending` -> `results` and the next round starts in the SAME room (CrazyGames rule). Players who press Play mid-round join at once (team balanced; party members share a team).
- Authority: the client moves itself (`pose`, bounded: `WORLD_BOUND`, `MAX_SPEED` + `MOVE_SLACK`, teleports only in the grace after a spawn). The shooter's client reports hits (`hit` { t, w, s shot number, n pellets, h head, d }); the server checks fire rate (per shot number, `FIRE_RATE_SLACK`), the weapon is in the loadout, teams, alive, spawn protection and range (server positions + `RANGE_SLACK`), then applies damage with armour (`rules.ts`, a copy of the client's config.js values) and decides knocks (a teammate standing), eliminations, assists, streaks, score and the round end. Frags: `throw` then `boom` { x, y, z, t: targets }; revives: `reviving` then `revive` after `HEALTH.reviveTime`; `heal`, `ult` (rook damage cut, jin heals), `fell`, `respawn` (>= `RESPAWN_MIN_S` after death), `open` crates/airdrops (armour is rolled here; crates refill on the round clock), zone damage / regen / bleed-out on the server tick. Relays for the others' eyes: `shot`, `throw`, `boom`, `wall`, `ult`, `emote`. Events sent: `dmg`, `knock`, `elim`, `revive`, `spawn`, `opened`, `matchEnd`, `round`, `rewards`.
- The zone is planned from the round's `zoneSeed` with `mulberry32` (`src/zone.ts`); the client's `src/game/zone.js` runs the same planner with the same call order, so both agree without streaming circles. `ISLAND_RADIUS` = the client island radius (125).
- Identity (`src/auth.ts`): `onAuth` verifies `options.token` (Legion.SDK.auth.getToken()) with `POST {BLOXITY_API_URL}/v1/auth/game-token/verify` and uses ONLY the returned `user._id`; no/refused token = `guest_<sessionId>` (never saved or reported). `options.devUser` (`dev-...`) is accepted only when `NODE_ENV !== "production"` (local dev saves). `auth` message re-verifies after a mid-session sign-in. One live session per account: a newer one closes the older with `REPLACED_CODE` (4100; the client does not rejoin after it).
- Looks: roster `avatar` (the client's Bloxity look JSON of ids, incl. `characterId`, max `AVATAR_MAX_LEN`) and `outfitKey` (from the verify response's `user.outfitKey` at join, then the player's own `avatar` { avatar, outfitKey } updates; `OUTFIT_KEY` pattern). Cosmetic only, relayed for the others' clients to dress the player.
- Progress (`src/db.ts`, `src/catalog.ts`): the player's profile (coins, rp, owned, loadout, upgrades, stats, mode) lives in Mongo under the verified id; `carriedFrom` guest saves seed a new account once (`carried`). The shop is server-side: `buy` / `equip` (coins only, prices copied from the client's config.js; nothing is sold for Gems), answers `shop` and `profile`; `getProfile` re-sends it. Round rewards (`REWARDS`) are granted at the results; leaving a running round pays half the fighting coins (no participation bonus) and costs rank.
- Bloxity reporting (`src/reporters.ts`, started in `index.ts`): `installRoomReporter` (Open Rooms directory via `MATCHMAKER_REPORT_URL`), leaderboard scores (`BOARDS` = the client's `LEADERBOARDS`) and player stats (`STAT_DEFINITIONS`) for verified `legion_` ids, batched every `REPORT_EVERY_MS` and at round end. All no-ops without `BLOXITY_REPORT_TOKEN` / `BLOXITY_GAME_ID`.
- Room options: `{ private: true }` = a private room (`?instantMultiplayer=true`, Play with friends). Metadata `{ mode: 1, modeName, started }`.
- CI/CD: `.github/workflows/deploy.yml` tests on PRs and pushes to `main`/`dev`; pushes also build+push a GHCR image and deploy to Bloxity Legion (`main` = prod, `dev` = dev), sending `roomSize` = `ROOM_MAX_CLIENTS` (18) read from `src/constants.ts` (keep it 2-100; never send `seatCap`, per docs.bloxity.io). Needs repo var/secret `LEGION_GAME_ID` (= `free-fire-zone`) and secret `LEGION_DEPLOY_TOKEN`.
- A rule or price change goes in both projects (client `src/config.js` + server `rules.ts` / `catalog.ts`).
